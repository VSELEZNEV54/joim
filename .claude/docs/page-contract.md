# JOIM Store: договор по страницам (второй круг, тёмная тема)

Что уже сделано общей частью, где лежат файлы каждой страницы, какие данные доступны в шаблонах, как собирать и кто что правит. Вид и классы компонентов описаны в `component-guide.md`; правки заказчика в `round2-brief.md` (читать целиком, обязательно разделы 3, 4, 6, 7, 7а, 8).

## 1. Что готово и что это значит для вас

Готово и общее для всех страниц (не переделывать, пользоваться):

- Шрифты Geist и Geist Mono, тёмные токены, сетка на всю ширину с полями `clamp(40px, 3.2vw, 60px)`.
- Шапка (тёмная, кнопка корзины это ссылка на `/cart/`), служебная полоса, панель каталога, мобильное меню, поиск, футер со ссылками на маркетплейсы.
- Кнопки, чипы, бейджи, поля форм, окна, аккордеон, крошки, таблицы, характеристики, лента с прокруткой, уведомление «Товар в корзине».
- Карточка товара в трёх вариантах (строка, «по две в ряд», плитка) с двумя кнопками маркетплейсов; та же разметка лежит в `data.js` для скриптов.
- Строка показателей (`.stats`), поля (`.fields`), рендер на странице без прямоугольника снимка (`.tile`, `.stage`), плитка категории (`.cat-tile`, `.mosaic`), светлые карточки (`.paper`, `.bp-card`, `.bracket-card`, `.review-card`).
- Главная целиком.

Не готово (ваши зоны): страничные стили каталога, товара, корзины, сравнения, подбора, доставки, отзывов, вопросов, избранного и заглушек написаны под прежнюю светлую версию. Общие компоненты на них уже тёмные, а свои блоки местами светлые, с жёсткими цветами и старыми именами токенов. Старые имена пока работают через переходный слой (раздел 23 main.css, см. `component-guide.md`, раздел 14): страницу нужно перевести на новые токены, а не опираться на него.

Три исполнителя: (1) каталог и категории; (2) страница товара; (3) корзина + сравнение + подбор + доставка + отзывы + вопросы + избранное + заглушки.

Общие файлы: `store/assets/css/main.css`, `store/assets/js/main.js`, `src/layout.html`, `src/partials/` (кроме `stub.html`), `build.mjs`, `src/data/products.json`, `src/routes.json`. Правила работы с ними:

- В свою страницу пишите всё страничное: классы с префиксом страницы (`cat-`, `pdp-`, `cart-`, `cmp-`, `pick-`, `dlv-`, `rev-`, `faq-`, `fav-`, `stub`), в свой `pages/*.css`.
- Общий компонент не переопределяйте глобально из страничного файла (не писать `.btn { … }` в `category.css`); подгонка только через свой класс или контекст (`.cat .product-card__title { … }`).
- Если общему компоненту не хватает варианта, добавляйте его в main.css отдельным модификатором, не меняя существующие правила: над этим файлом одновременно работают трое, а главная на него опирается. После правки main.css или partial пересоберите всё и посмотрите главную.
- `src/data/products.json`: факты (цены, характеристики, тексты, отзывы) не менять и не добавлять. Можно добавлять служебные поля подгонки картинок (как `tile`, `stage`).
- `store/*.html` и `store/assets/js/data.js` создаёт сборка: руками не править.
- Архивы (`_archive-*`) и `src/legacy/` не трогать и не использовать как источник стилей; `_archive-v4-kepaqi-light/` это принятая светлая версия: её структура страниц и тексты остаются.

## 3. Сборка и просмотр

```
node build.mjs              всё: 41 адрес (8 страниц из src/pages, 5 категорий, 8 товаров, 20 заглушек) + data.js, sitemap.xml, robots.txt
node build.mjs cart         одна страница по имени файла src/pages/<имя>.html (можно несколько имён)
node build.mjs category     пять категорий из шаблона
node build.mjs product      восемь товаров из шаблона
node build.mjs stubs        заглушки
node build.mjs --list       показать адреса и их исходники
```
Запускать из корня проекта. Нужный итог: строка «Готово: N стр.» без блока «Замечания» и без «Ошибки». Сборка проверяет: длину `title` (до 65) и `description` (140–160), ровно один `h1`, `alt`, `width`, `height` у картинок, разбор JSON-LD, ссылки-заглушки на маркетплейсы (поисковых ссылок быть не должно), `rel="noopener"` у `target="_blank"`, нераскрытые вставки `{{…}}`, повторы `id`, ссылки в никуда (внутренние адреса и якоря), `aria-*` и `for`, ссылающиеся на несуществующие `id`.

Страничные `css` и `js`, названные в мете, сборка создаёт пустыми, если их нет; существующие не трогает. Правки в `store/assets/css` и `store/assets/js` пересборки не требуют, правки в `src/` требуют.

Просмотр: `http://localhost:4173/` (корень сайта это папка `store`; сервер `node .claude/serve.mjs store 4173`). Инструменты: `.claude/tools/shot.mjs` (кадры по экранам и отчёт: высота, битые картинки, ошибки консоли и сети, шрифты, горизонтальное переполнение), `probe.mjs` (выполнить JS в странице и снять кадр после), `sheet.mjs` (контактный лист). По одному экземпляру за раз.

## 4. Шаблонизатор (build.mjs)

```
{{имя}}                 значение с экранированием HTML          {{{имя}}}            значение как есть (в данных уже есть &nbsp; и теги)
{{a.b.c}}               вложенное поле: {{products.es19.url}}, {{{products.es19.specs.current}}}
{{#if имя}}…{{else}}…{{/if}}     условия: имя · !имя · имя == "строка" · имя != "строка" · a == b (вложенность разрешена)
{{#each список}}…{{else}}…{{/each}}   внутри: поля элемента, this, index, number, first, last, head (первые четыре), odd, even
{{> partial арг ключ=значение}}  вставка src/partials/partial.html; первый аргумент без имени = id товара (или переменная с id)
{{icon имя [класс]}}    иконка из спрайта            {{price es19}}  цена товара с неразрывными пробелами
{{json имя}}            значение как JSON-строка без тегов и сущностей (для JSON-LD)
```
- Неизвестная переменная или partial дают замечание сборки, а не пустоту.
- Истинность: непустая строка, число не ноль, непустой массив. Пустой массив в `{{#each}}` уходит в `{{else}}`.
- Значение аргумента partial сначала ищется как переменная, иначе берётся строкой: `view=row` даёт строку `row`, `eager=head` даёт значение `head` текущего элемента цикла, `cls=bp-card__art` строку.
- Строковое поле можно проверить по первому знаку: `{{#if src.0 == "/"}}` (локальный файл).
- Комментарии HTML в исходнике попадают в страницу как есть: вставки `{{…}}` внутри комментария тоже раскрываются.

### Мета страницы

`src/pages/<имя>.html` начинается с блока:
```html
<!--page
{
  "path": "/cart/",                 обязательно, с «/» в начале и в конце
  "title": "…",                     обязательно, до 65 знаков
  "description": "…",               обязательно, 140–160 знаков
  "h1": "…",                        обязательно (идёт в крошки, если нет crumb)
  "crumb": "Короткое имя",          необязательно: имя в крошках
  "parents": [{ "name": "Каталог", "path": "/catalog/" }],   промежуточные крошки
  "nav": "catalog",                 пункт меню: catalog | podbor | delivery | reviews | faq | about | contacts | compare | gifts | blog
  "css": ["pages/cart.css"], "js": ["pages/cart.js"],
  "robots": "noindex, follow",      необязательно (корзина и избранное закрыты от индекса)
  "darkTop": true,                  страница начинается с экрана-сцены: шапка над ним прозрачная до первой прокрутки
  "bodyClass": "…", "ogImage": "…", "ogType": "…", "preloadImage": "/assets/img/…"  (строка, список или { href, srcset, sizes })
}
-->
```
Пустое тело страницы (после меты только комментарии) превращает её в заглушку. `title`, `description`, `h1`, `path`, JSON-LD существующих страниц не менять.

Шаблоны `src/templates/category.html` и `product.html` начинаются с `<!--template { "css": […], "js": […] } -->`; остальную мету сборка берёт из справочника (у категории её поля, у товара `title`, `description`, `name`). Класс на `body`: `page-<имя>` у страниц, `page-category cat-<id>` у категорий, `page-product product-<id>` (+ `is-soon`) у товаров, `page-stub` (+ `bodyClass` из routes.json) у заглушек.

Каркас страницы (`src/layout.html`): служебная полоса, шапка, `<main id="main" class="main">`, крошки (собирает сборка), ваше содержимое, футер, меню, общие окна, `data.js`, `main.js`, ваш скрипт (`defer`).

id товаров: `es19`, `es29`, `pvc1` (в продаже), `es2`, `es55`, `es99`, `pvc7`, `pvc8` («скоро»). id категорий: `all`, `puskovye`, `kompressor`, `dizel`, `pylesosy`.

### Поля товара

Исходные (из `src/data/products.json`) и вычисленные сборкой. В шаблоне товара и внутри `{{#each}}` по товарам они доступны без префикса, на остальных страницах через `products.<id>.`

| Поле | Содержимое |
|---|---|
| `id`, `name`, `short`, `model` | `es19`, «Пусковое устройство JOIM Easy Start ES-19», «Easy Start ES-19», «ES-19» |
| `nameHtml`, `shortHtml` | то же для разметки (модель не рвётся по дефису, предлог не висит): вставлять тройными скобками |
| `type`, `typeName` | `jump` или `vacuum`; «Пусковое устройство» или «Автомобильный пылесос» |
| `cats`, `cat`, `catName`, `catPath` | категории товара; первая из них объектом, её имя и адрес |
| `status`, `inStock`, `soon` | `in_stock` или `soon`; логические флаги |
| `price`, `priceFmt`, `priceHtml` | число (у «скоро» нет); строка «5 837 ₽» или «Скоро в продаже»; она же с `&nbsp;` (тройные скобки) |
| `rating`, `reviews`, `hasRating`, `ratingFmt`, `reviewsFmt`, `reviewsHtml` | 5; 8; флаг; «5,0»; «8 отзывов»; с `&nbsp;` |
| `badge`, `badgeTone` | «Хит продаж» или «Скоро» (или пусто); `accent` или `soft` |
| `url`, `ozonUrl`, `wbUrl` | адрес страницы товара; магазин JOIM на Ozon; бренд JOIM на Wildberries (у всех восьми одинаковые, поле у каждого) |
| `img`, `w`, `h`, `alt`, `fit` | вертикальный кадр серии для плитки, размеры, alt, `tall` или `wide` |
| `tile`, `tileStyle`, `tileMod` | подгонка кадра в плитке: объект, готовая строка для `style`, модификатор маски |
| `stage`, `stageStyle` | широкий кадр `*-stage.jpg`: `stage.src`, `stage.w`, `stage.h`; строка переменных для `style` |
| `cutImg`, `cutW`, `cutH` | вырезка на прозрачном фоне; есть только у `es19`, `es29`, `pvc1` (адреса на сайте клиента) |
| `gallery` | кадры галереи: `src`, `w`, `h`, `alt`, `bg` (`dark` или `light`), `dark`, `light`, `video`, `isVideo`, `n`, `first` |
| `specsHtml` | строка ключевых цифр: «3 300 А · до 8 л бензин · 20+ запусков» |
| `specs` | характеристики по ключу: `{{{specs.current}}}` |
| `specList` | характеристики списком для таблицы: `key`, `name`, `value` (без служебных) |
| `fieldList` | поля карточки каталога: `label`, `valueHtml` (3–4 штуки, задаются полем `fields`) |
| `usage`, `usageLine` | «для чего» списком; первые три через точку одной строкой |
| `about`, `aboutText` | описание с разметкой; оно же чистым текстом |
| `kit` | комплектация списком строк (`{{#each kit}}<li>{{{this}}}</li>{{/each}}`) |
| `reviewItems` | отзывы этого товара: `name`, `text`, `dateIso`, `dateFmt` (дословно, не править) |
| `steps` | «Как пользоваться»: пять шагов, только у пусковых в продаже (`{{#each steps}}{{{this}}}`, номер `{{number}}`) |
| `limitPetrol`, `limitDiesel` | пределы объёма для подбора (только `es19`) |
| `title`, `description` | мета страницы товара |

Подгонка картинок (служебные поля, их можно править; фактов в них нет):
- `tile`: `scale` (масштаб кадра в плитке 5:6: доля высоты плитки у `tall`, доля ширины у `wide`), `x`, `y` (сдвиг в процентах кадра), `tone` (яркость), `fade`, `fb` (длина растворения верха и низа, %), `rot` (поворот, градусы), `mod` (`corner` или `float`: вид маски), `duo` (предел ширины кадра в карточке «по две в ряд», % ширины плитки; по умолчанию 114).
- `stage`: `src`, `w`, `h` (кадр `*-stage.jpg` и его размеры), `cx`, `cy` (центр товара в кадре, %), `s` (высота кадра в долях высоты окна), `fl`, `fr`, `ft`, `fb` (длина растворения краёв, %), `tone`.

Ключи `specs` по товарам:
- `es19`, `es29`: `current`, `currentType` (служебный), `voltage`, `engines`, `starts`, `capacity`, `battery`, `temp`, `lamp`, `ports`, `size`, `warranty`; у `es19` ещё `caseSize`, `clamps`; у `es29` ещё `adapter`.
- `pvc1`: `motor`, `runtime`, `charge`, `filters`, `modes`, `body`, `length`, `hose`, `warranty`.
- `es2`: `current`, `engines`, `starts`, `lamp`, `ports`, `display`. `es55`, `es99`: то же и `compressor`.
- `pvc7`: `format`, `kitSet`, `storage`. `pvc8`: `format`, `container`, `kitSet`.

Обращение к ключу, которого у товара нет, даёт замечание сборки: в общем шаблоне пользуйтесь `{{#each specList}}`, `{{#each fieldList}}` или условием по id. Значения уже содержат `&nbsp;`: вставлять тройными скобками. Полоса ключевых цифр на странице товара собирается из этих же значений (число и подпись), новых цифр не добавлять; у моделей «скоро» показывать 2–4 показателя, сколько есть в данных.

Только в шаблоне товара: `p` (сам товар, чтобы сравнивать внутри циклов: `{{#if id != p.id}}`), `related` (четыре товара для «Вам может быть интересно»), `isJump`, `isVacuum`.

## 6. JS-API (`window.JOIM`, файл main.js)

Страничный скрипт подключается после `data.js` и `main.js` (`defer`), поэтому `window.JOIM` уже есть.

| Имя | Что делает |
|---|---|
| `JOIM.catalog` | товары по id (для скрипта): `id`, `name`, `short`, `model`, `type`, `typeName`, `cats`, `status`, `price`, `url`, `ozonUrl`, `wbUrl`, `img`, `w`, `h`, `fit`, `rating`, `reviews`, `badge`, `specsHtml` (строка ключевых цифр, HTML), `cutImg`, `cutW`, `cutH` (если есть), `limitPetrol`, `limitDiesel` (только `es19`) |
| `JOIM.order` | id товаров в порядке каталога |
| `JOIM.categories` | `id`, `name`, `chip`, `path`, `thumb`, `count` |
| `JOIM.cardHtml(id, view)` | готовая разметка карточки: `view` = `'tile'` (по умолчанию), `'duo'`, `'row'`. После вставки: `JOIM.fav.sync(контейнер)` |
| `JOIM.canBuy(id)` | товар в продаже и с ценой |
| `JOIM.cart` | `items()` (товар + `qty`, `sum`), `count()`, `total()`, `add(id, qty)` (для «скоро» вернёт `false`), `setQty(id, qty)` (меньше 1 удаляет), `remove(id)`, `clear()`, `open()` (переход на `/cart/`) |
| `JOIM.cartUrl`, `JOIM.freeDeliveryFrom` | `/cart/`; 15000 |

**Страница товара** (бриф, раздел 6).
